# Android 逆向需求分析 (1) — 环境选型：模拟器 / 云手机 / 真机

> 选错环境，一半的工具链和对抗手段都用不上。这篇把三类环境的取舍讲清楚。

## 一、为什么环境选型是第一道门槛

很多逆向需求卡住，不是算法难，而是**目标 APP 对运行环境有检测**：
root 检测、模拟器特征检测、SIM/网络环境检测、机型指纹检测。
先确认目标在哪个环境能正常跑起来，再谈抓包和脱壳。

## 二、三类环境对比

| 维度 | 真机 (Root) | 模拟器 (雷电/MuMu/Genymotion) | 云手机 |
|---|---|---|---|
| 真实度 | ★★★★★ | ★★ | ★★★★ |
| 检测对抗难度 | 低（最像真机） | 高（特征多） | 中 |
| 可批量 | ✗ | ✓（本地多开） | ✓✓（无限扩容） |
| Frida 注入 | 稳定 | 稳定 | 看厂商是否支持 |
| 成本 | 一台机器 | 免费/低 | 按时计费 |
| 适合场景 | 单机深度分析、付费 APP、强检测目标 | 快速验证、批量脚本 | 群控、规模化采集、多地区 |

## 三、选型决策树

1. 目标有**强模拟器检测 + 付费/金融属性** → **真机 (Magisk + Zygisk + LSPosed)**
2. 目标是**普通工具/社交类，需批量** → **模拟器**（雷电/MuMu 性价比高，Genymotion 调试友好）
3. 目标需要**多地区 IP + 大规模并发** → **云手机**（注意选支持 Frida/adb 调试的厂商）

## 四、真机环境推荐配置

- 机型：一加 / 小米开发版 / Google Pixel（解锁 Bootloader 友好）
- Root：Magisk + Zygisk
- 模块：Shamiko（隐藏 root）、LSPosed（hook 框架）
- 内核：可选 Frida-server-gadget 或编译定制内核

## 五、小结

> 环境是逆向的「地基」。先让目标在选定环境里**正常跑、能联网、能抓包**，再进入协议与算法层。
