# Android 逆向需求分析 (2) — 主流加固方案对比

> 加固决定脱壳成本。先认壳，再选脱壳方案。

## 一、为什么要分清加固

不同加固方案的脱壳思路完全不同：有的内存 dump 就行，有的要主动调用、修 VMP、甚至硬啃 OLLVM。
拿到 APK 第一步先判断**是哪类壳、什么版本**，再决定工具链。

## 二、主流加固对比（2026 视角）

| 加固类型 | 特征 | 脱壳难度 | 主流脱壳思路 |
|---|---|---|---|
| 免费壳（梆梆免费/360 免费/腾讯御安全） | 入门级，dex 加密落地 | ★ | 内存 dump（FART / BlackDex / frida-dexdump） |
| 企业壳（梆梆企业/爱加密/通付盾/娜迦） | 抽取/指令抽取、so 还原 | ★★★ | 主动调用 + dump、修复被抽方法 |
| Java2C（DEX 虚拟化） | 关键方法转 C，dex 里只剩壳 | ★★★★ | 还原 native 化逻辑，结合 so 分析 |
| VMP（虚拟机保护） | 方法转自定义字节码 | ★★★★★ | 分析 VM 解释器，写反汇编器 |
| OLLVM（so 层混淆） | 控制流平坦化/虚假控制流 | ★★★★ | 反混淆（D810 / 去平坦化脚本）+ 半自动 |
| Flutter / RN | 非 JVM 体系 | ★★★★ | 内存搜 Dart snapshot、桥接层 hook |

## 三、脱壳工具链速查

- **内存 dump**：FART（Magisk 模块）、BlackDex、frida-dexdump、Youpk
- **Hook**：Frida + LSPosed
- **静态**：Jadx、JEB、GDA
- **Native**：IDA Pro、Ghidra、unidbg（模拟执行 so）
- **反混淆**：D810（OLLVM）、定制 IDA 脚本

## 四、脱壳后还要做什么

> 脱壳只是第一步。拿到 dex 后真正值钱的是 **so 层的签名/加密算法**——这才是协议还原的核心。

1. 修运行：脱出的 dex 能否独立运行（缺失方法补齐）
2. 定位算法：在 so 里找目标函数（JNI 注册表 / 字符串 / 交叉引用）
3. 模拟执行：用 **unidbg** 把 so 跑起来，直接拿输入输出，省去硬啃汇编
4. 转语言：把算法翻译成 Python / Go，交付可复现脚本

## 五、小结

> 认壳 → 选工具 → dump 修运行 → 进 so 找算法 → 模拟执行 → 转语言交付。
